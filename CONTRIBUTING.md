# Contributing

Thanks for helping. The most valuable contribution is a **report of an endpoint
that changed**, with the output of `gtrends-mcp-full doctor`.

## Setup

```sh
git clone https://github.com/mamrrez/gtrends-mcp-full && cd gtrends-mcp-full
uv venv && uv pip install -e ".[dev]"
uv run pytest
uv run ruff check --fix
```

Tests need no network: the tools run against a fake Google Trends in
`tests/conftest.py` that answers the same URLs in the same wire formats, with
synthetic data whose shape is known (a term that peaks every July, one that is
rising, one that spikes).

## How the code is laid out

| Module | What it holds |
|---|---|
| `client.py` | Every request to Google: the session cookie, pacing, back-off, the cache, parsing |
| `timeframes.py`, `analysis.py`, `geo.py`, `format.py`, `matching.py` | Pure functions, no network |
| `store.py` | The SQLite file: cache, trending snapshots, watchlist |
| `runtime.py` | Shared state and input parsing for the tools |
| `tools_core.py`, `tools_analysis.py`, `tools_history.py`, `prompts.py` | The MCP surface |

## The recorded answers

`tests/fixtures/` holds one real answer from every endpoint, and
`tests/test_contract.py` replays them through the real parser and checks that
the fake uses no field Google does not send. To refresh them — about 15 paced
requests to Google, so do it rarely and on purpose:

```sh
python scripts/record_fixtures.py
```

Signed tokens are replaced by a placeholder and long lists are cut to a sample;
no cookies or headers are stored.

## When Google changes an endpoint

1. `gtrends-mcp-full doctor` says which endpoint fails and how.
2. The request and the parsing for each endpoint are in `client.py`, next to each other.
3. Record the answers again (above): the contract tests now fail at the exact field that changed.
4. Fix the client, then bring the fake in `tests/conftest.py` in line with the new format.

## Adding a tool

Tools are thin: get data through the client, call a pure function in
`analysis.py`, format with `format.py`. Put the logic in the pure
function and test it there; add one end-to-end test through the fake. Keep
output compact — cap rows and say so — and say what a number is (an index, a
share, a count).

## Pull requests

- One change per PR, with a line in `CHANGELOG.md` under *Unreleased*.
- `ruff` clean, `pytest` green on 3.10.
- The tool reference (`docs/tools.md`) is generated by `scripts/gen_tools_doc.py` — run it if you changed a tool signature or docstring.
